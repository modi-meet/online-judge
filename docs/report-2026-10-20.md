## fixed today while testing

1. **linux ci failed every golden fixture.** macos had hidden two sandbox bugs: `mkdtemp` makes a 0700 dir the sandbox uid cannot read, and the oom killer takes the program rather than the `time` wrapper so docker reports no oom. both fixed; ci green.
2. **submit button stayed disabled after a verdict.** the hook closed the sse stream on the first terminal event, before the row with `judgedAt` arrived. fixed by marking judged and re-reading the row.
3. **submissions list did not refresh** after a verdict on the same page. effect dependency fixed.
4. **validation errors were generic** in the ui. now the field is named.
5. **malformed json was a 500.** now a 400 envelope.
6. **load generators hit the per-ip login bucket** (correct behaviour). token pool seeder added so load runs do not go through the api to authenticate.
7. **redis-flush drill** exposed that the projector was not running; the drill itself was right.

## partially done

- **cpu time resolution.** cpu time comes from gnu `time` (10 ms resolution), not the cgroup, because cgroup files are unreachable from a macos host. the lld calls for cgroup `cpu.stat` on linux workers; not implemented. consequence: fast programs show `0 ms`, and tle at the 1 s boundary is ±10 ms.
- **ai mentor against the real provider.** the anthropic path is written (opus 5.5 strong / haiku 5.5 fast, server-side fallbacks, prompt caching) and typechecks against the sdk, but this machine has no api key, so every live run used the fake provider. the first real run should be watched for prompt quality and token spend.
- **mode 3 tracing is python-only.** other languages get the real sample run (stdout vs expected) without a line trace.
- **mode 4 input generator** understands "n, then n integers". other input shapes are reported as inconclusive with a reason.
- **leak guard rules b and c** (editorial similarity) have tests but no editorial field in the schema yet, so only rule a fires in practice.
- **load test** is a laptop burst. the k6 contest profile is written but k6 is not installed here; the hld §7 capacity table still holds estimates.
- **rejudge** exists as an api endpoint (setter) with tests; no button in the web ui.
- **standings on rejudge**: a verdict that changes from ac to wa cannot un-solve a problem in the projection; a rebuild fixes it.

## left

- **deployment** (yours): nothing has run on a cluster. `infra/` has the prod compose, dockerfiles, nginx gateway, keda worker manifests, blue/green api and `promote.sh`. the ingress, secrets, s3 bucket and the read-only mongo user for the mentor are not written.
- **site scrapers.** the ingestor has the adapter interface and a file adapter. no codeforces or other site adapter: it needs a licence decision per source, and scraping statements has terms-of-service implications the `license` field exists to record.
- **kafka.** gated until a second consumer of judged events exists (hld §12). redis streams sit behind the same transport interface.
- **plagiarism, payments, mobile, collaborative editing**: out of scope by the hld.
- **web tests.** the web app has typechecks and manual verification only; no component tests.
- **security review of the sandbox on linux**: the golden suite covers network, scratch write, `/etc/shadow`, fork bomb; a seccomp profile is wired but the default is unconfined in dev. an external review before public exposure is advisable.

## how to run it

```bash
nvm use && pnpm install && pnpm stack:up
pnpm --filter @oj/db migrate && pnpm --filter @oj/db seed
runners/build.sh dev
# then from .claude/launch.json or by hand: api, web, judge-worker, outbox-relay, leaderboard-projector, ai-mentor
```

tests: `pnpm -r test`. drills: `chaos/*.sh`. load: `node load/seed-users.mjs && node load/burst.mjs`.
